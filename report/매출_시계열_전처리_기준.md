# 매출 시계열 분석 · 예측 전처리 기준

이 문서는 날짜 단위 매출 데이터를 시계열 분석/지수평활법 예측에 사용하기 전 거쳐야 할 전처리 단계와, 각 단계에서 사용할 구체적인 계산식을 정의한다. 원본 데이터는 수정하지 않고, 전처리 결과는 별도 파일로 저장한다.

## 1. 날짜 처리

- 날짜 칼럼을 `datetime` 타입으로 변환한다 (`pd.to_datetime(df['날짜'], errors='coerce')`).
- 변환 실패(파싱 불가) 행은 몇 건인지 집계해서 보고하고, 원인을 확인한 뒤 제외 여부를 결정한다.
- 날짜 기준 오름차순 정렬 후 인덱스를 재설정한다.
- 하루 단위로 데이터가 1행씩 존재하는지 확인한다. 같은 날짜에 여러 행(지점별/상품별 등)이 있다면 분석 목적에 맞는 집계 키(합계 또는 평균)를 먼저 정의한다.

## 2. 빠진 날짜(결측 날짜) 처리

- 전체 날짜 범위: `pd.date_range(start=최소날짜, end=최대날짜, freq='D')`
- 실제 존재하는 날짜와 비교해 빠진 날짜 목록과 개수를 산출한다.
- 빠진 날짜는 다음 기준으로 채운다.
  - 매장이 실제로 휴무였던 날(공휴일, 정기휴무 등 확인 가능한 경우): 매출 0으로 채움.
  - 원인 불명의 결측(시스템 오류 등으로 추정): 명시적으로 빈 값(NaN)으로 남기고, 이후 보간 여부는 별도로 결정. 임의로 평균/이동평균값을 채워 넣지 않는다.
- 채운 방식(0 처리 vs 결측 유지)과 건수를 반드시 기록한다.

## 3. 중복 데이터 처리

- 날짜 기준 중복 행 개수를 확인한다 (`df.duplicated(subset=['날짜'], keep=False)`).
- 중복이 동일 값의 완전 중복이면 하나만 남기고 제거한다.
- 중복이 서로 다른 값(예: 지점별 매출이 나뉘어 있는 경우)이면 제거 대신 먼저 집계(합계)로 하루 1행으로 만든다.
- 제거/집계한 행 수와 기준을 기록한다.

## 4. 이상치 탐지 기준

- **음수/논리적 오류값**: 매출이 음수이거나 불가능한 값이면 오류로 간주하고 목록화한다. 환불 등으로 음수가 정상 범위인 경우 별도 표시만 하고 삭제하지 않는다.
- **통계적 이상치 (IQR 1.5배 기준)**
  - `Q1 = 매출.quantile(0.25)`, `Q3 = 매출.quantile(0.75)`, `IQR = Q3 - Q1`
  - 정상 범위: `[Q1 - 1.5*IQR, Q3 + 1.5*IQR]`
  - 범위를 벗어나는 값은 이상치 후보로 표시(플래그 칼럼 추가)하되, 삭제하지 않고 원인(프로모션, 명절, 시스템 오류 등)을 먼저 확인한다.
- 이상치는 예측 모델 학습 시 제외할지, 가중치를 낮출지, 그대로 둘지를 원인 확인 후 결정하고 근거를 기록한다.

## 5. 파생 변수 생성

- `요일`: `dteday.dt.dayofweek` 또는 문자열 라벨(월~일)
- `is_weekend`: 토/일 여부 (Boolean)
- `월`, `분기`: `dteday.dt.month`, `dteday.dt.quarter`
- `공휴일 여부`: 공휴일 목록(별도 파일 또는 `holidays` 라이브러리)과 대조해 0/1로 표시
- `프로모션/이벤트 여부`(있는 경우): 별도 마스터 데이터와 조인

## 6. 추세·계절성 파악을 위한 이동평균 계산

- **중심 이동평균(추세, trend)**: `매출.rolling(window=7, center=True, min_periods=7).mean()`
  - 앞뒤 3일씩(당일 포함 7일) 평균. 양 끝 3일은 비교 대상이 없어 빈 값(NaN)으로 남긴다.
- **요일효과(seasonal, 요일 주기)**
  1. `resid1 = 매출 - trend`
  2. `요일평균 = resid1.groupby(요일).mean()`
  3. `요일효과 = 요일평균 - 요일평균.mean()` (합이 0이 되도록 정규화)
- **잔차(residual)**: `잔차 = 매출 - trend - 요일효과`
- 분해식: `매출 = trend + 요일효과 + 잔차`
- 잔차 절대값 상위 N개 날짜는 별도로 뽑아 이벤트/이상치 여부를 확인한다.

## 7. 로그 변환 여부 판단

- 매출 변동폭이 시간이 갈수록 커지는 패턴(변동성이 수준에 비례)이 보이면 로그 변환(`log(매출+1)`)을 검토한다.
- 승법(multiplicative) 계절성으로 보이면 로그변환 후 가법 모델을 적용하거나, Holt-Winters 승법 모델을 직접 사용한다.

## 8. 학습/평가 데이터 분할 기준

- 시계열이므로 무작위 분할(shuffle) 금지.
- 마지막 N일(예: 최근 30일 또는 전체의 마지막 10~20%)을 평가(test) 구간으로 고정하고, 그 이전 구간을 학습(train)으로 사용한다.
- 평가지표: `MAE`, `RMSE`, `MAPE`를 함께 계산해 보고한다.
  - `MAPE = mean(|실제값 - 예측값| / 실제값) * 100` (실제값 0인 날짜는 분모 0이 되므로 제외하거나 별도 처리)

## 9. 지수평활법(Exponential Smoothing) 모델 선택 기준

추세/계절성 존재 여부를 6번 분해 결과로 먼저 판단한 뒤 아래 기준으로 모델을 선택한다.

| 추세 | 계절성 | 모델 |
|---|---|---|
| 없음 | 없음 | 단순지수평활(SES), 평활계수 α |
| 있음 | 없음 | Holt's Linear Trend, α(수준) + β(추세) |
| 있음 | 있음(요일 주기=7) | Holt-Winters, α + β + γ(계절), `seasonal_periods=7` |

- 평활계수(α, β, γ)는 임의로 고정하지 않고, 학습 구간에서 SSE(오차제곱합) 최소화 기준으로 최적화한다 (`statsmodels`의 `optimized=True` 사용).
- 계절 유형(가법 vs 승법)은 9번 로그변환 판단 결과와 연결해서 선택한다.

## 10. 기록 원칙

- 각 단계에서 제외/대체/보정한 데이터는 기준과 건수를 별도로 남긴다.
- 계산에 사용하는 값은 원 정밀도를 유지하고, 화면 출력 시에만 반올림한다.
- 모든 전처리는 재실행 가능한 Python 스크립트로 작성하고, 원본(`data/raw`)은 그대로 두고 결과는 `data/processed`에 저장한다.
